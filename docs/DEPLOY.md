# Развёртывание на сервере

Инструкция для человека без опыта программирования. Итог: приложение работает по адресу
`https://ваш-домен`, сертификат HTTPS выдаётся и продлевается сам, база каждый день копируется.

Что понадобится: арендованный сервер (VPS), домен, аккаунт GitHub с доступом к репозиторию и около часа времени.

---

## 1. Сервер (VPS)

### Почему сервер должен быть в Казахстане

В базе хранятся персональные данные кандидатов: ФИО, телефоны, переписка. Закон РК
«О персональных данных и их защите» (статья 12) требует хранить базы, содержащие персональные данные
граждан Казахстана, на территории Республики Казахстан. Поэтому берите сервер у казахстанского хостинга
с дата-центром в РК (например, PS.kz, Hoster.kz или другой), а не у зарубежного провайдера.

### Какой сервер заказать

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| Процессор | 2 ядра (vCPU) | 2–4 ядра |
| Память | 2 ГБ | 4 ГБ |
| Диск | 30 ГБ SSD | 50 ГБ SSD/NVMe |
| Система | **Ubuntu 24.04 LTS** | Ubuntu 24.04 LTS |
| IP-адрес | 1 публичный IPv4 | — |

При заказе выберите образ **Ubuntu 24.04**. После оплаты хостинг пришлёт (на почту или в личном кабинете):
**IP-адрес** сервера, логин (обычно `root`) и **пароль**. Сохраните их.

## 2. Домен

1. Купите домен у любого регистратора (для `.kz` — у аккредитованного регистратора, часто это тот же хостинг).
   Можно использовать поддомен уже имеющегося сайта компании, например `hr.company.kz`.
2. В панели управления DNS домена создайте **A-запись**:
   - Имя (хост): `hr` для адреса `hr.company.kz`, или `@` — если приложение будет на самом домене;
   - Тип: `A`;
   - Значение: **IP-адрес вашего сервера**;
   - TTL: можно оставить по умолчанию.
3. Обновление DNS занимает от нескольких минут до нескольких часов. Проверить можно на сайте
   dnschecker.org: введите домен — там должен появиться IP сервера.

Домен на кириллице (`.қаз`) указывайте в скрипте в виде punycode (`xn--...`); проще взять латинский.

## 3. Подключение к серверу по SSH

Все команды ниже вводятся в окне подключения к серверу.

**Windows 10/11.** Нажмите «Пуск», введите `PowerShell`, откройте. Введите (вместо `IP` — адрес сервера):

```
ssh root@IP
```

**macOS.** Откройте «Терминал» (Программы → Утилиты → Терминал) и введите ту же команду.

При первом подключении появится вопрос `Are you sure you want to continue connecting?` — напишите `yes`
и нажмите Enter. Затем введите пароль от сервера. **Символы пароля при вводе не отображаются** — это нормально,
просто наберите его (или вставьте правой кнопкой мыши) и нажмите Enter.

Если хостинг выдал не `root`, а другого пользователя, войдите под ним и выполните `sudo -i`.

## 4. Токен GitHub для скачивания кода

Репозиторий закрытый, поэтому серверу нужен ключ только для чтения.

1. Войдите на github.com под аккаунтом с доступом к репозиторию.
2. Аватар справа вверху → **Settings** → внизу слева **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
3. Заполните:
   - **Token name:** `hr-server`;
   - **Expiration:** срок действия (например, 1 год; после окончания обновления с сервера перестанут скачиваться — нужно будет выпустить новый токен);
   - **Resource owner:** владелец репозитория;
   - **Repository access:** *Only select repositories* → выберите `hr-messenger-mvp`;
   - **Permissions → Repository permissions → Contents:** **Read-only** (остальное не трогайте).
4. Нажмите **Generate token** и скопируйте токен (начинается с `github_pat_`). Он показывается один раз.

Токен даёт только чтение одного репозитория. Никому его не пересылайте.

## 5. Установка одной командой

Скопируйте команду в блокнот, замените `ТОКЕН` на свой токен, затем вставьте в окно сервера и нажмите Enter:

```bash
apt-get update && apt-get install -y git && git clone https://ТОКЕН@github.com/ViktoriyaStremetskaya1/hr-messenger-mvp.git /opt/hr-messenger && bash /opt/hr-messenger/scripts/server-setup.sh
```

Скрипт спросит **домен** (например `hr.company.kz`, без `https://`) и дальше всё сделает сам:

1. установит Docker, Git и файрвол (снаружи открыты только SSH и порты 80/443);
2. создаст файл настроек `/opt/hr-messenger/.env` со случайными ключами;
3. проверит, что домен указывает на этот сервер;
4. соберёт и запустит приложение (первый раз 5–15 минут);
5. получит HTTPS-сертификат;
6. включит ежедневную резервную копию базы;
7. предложит создать администратора (см. следующий раздел).

Если установка прервалась (обрыв связи, ошибка), просто запустите ещё раз — уже сделанное не повторяется, данные не теряются:

```bash
bash /opt/hr-messenger/scripts/server-setup.sh
```

## 6. Администратор и первый вход

В конце установки скрипт спросит «Создать администратора сейчас?». Ответьте Enter (да), затем введите:
- **логин** латиницей, например `admin`;
- **ФИО**;
- **пароль** дважды — не меньше 10 символов, при вводе не отображается.

Создать администратора позже или **сбросить забытый пароль** (учётная запись заодно снова станет активной):

```bash
cd /opt/hr-messenger
docker compose exec api python -m app.create_admin --login admin --name "Фамилия Имя"
```

Откройте в браузере `https://ваш-домен` и войдите. Остальных сотрудников администратор добавляет
в разделе «Пользователи».

> Тестовые данные (`python -m app.seed`) на боевом сервере **не запускайте**.

## 7. Ключи шифрования — сохраните обязательно

Телефоны кандидатов хранятся в базе в зашифрованном виде. Ключи лежат в `/opt/hr-messenger/.env`
(`PHONE_ENC_KEYS` и `PHONE_HASH_KEY`); скрипт выводит их в конце установки.
**Если сервер пропадёт, а ключей не будет, телефоны из резервных копий восстановить невозможно.**

Скачайте весь файл `.env` к себе и храните в менеджере паролей или другом надёжном месте (не в почте и не в мессенджере).
На своём компьютере (не на сервере) в PowerShell или Терминале:

```
scp root@IP:/opt/hr-messenger/.env hr-messenger.env
```

## 8. Подключение WhatsApp (Meta)

Как получить номер, токен и секрет приложения — в [WHATSAPP_SETUP.md](WHATSAPP_SETUP.md), разделы 1–3.

1. На сервере откройте файл настроек:
   ```bash
   nano /opt/hr-messenger/.env
   ```
   Заполните `WA_PHONE_NUMBER_ID`, `WA_BUSINESS_ACCOUNT_ID`, `WA_ACCESS_TOKEN`, `WA_APP_SECRET`, `WA_DISPLAY_PHONE`.
   `WA_API_BASE=https://graph.facebook.com` уже указан. Сохранить: `Ctrl+O`, Enter; выйти: `Ctrl+X`.
2. Перезапустите приложение:
   ```bash
   cd /opt/hr-messenger && docker compose --profile prod up -d
   ```
3. В кабинете Meta: WhatsApp → Configuration → Webhook:
   - **Callback URL:** `https://ваш-домен/api/webhooks/whatsapp`
   - **Verify token:** значение `WA_VERIFY_TOKEN` из `.env` (скрипт выводит его в конце установки;
     посмотреть: `grep WA_VERIFY_TOKEN /opt/hr-messenger/.env`)
   - подпишитесь на поле **messages**.

## 9. Обновление

Когда разработчик сообщит о новой версии:

```bash
bash /opt/hr-messenger/scripts/update.sh
```

Скрипт сделает резервную копию, скачает новую версию, пересоберёт и перезапустит приложение.
Изменения структуры базы применяются автоматически при запуске. Перерыв в работе — около минуты.

## 10. Резервные копии и восстановление

- Копия базы делается **каждый день в 03:30** по времени сервера в `/opt/hr-messenger/backups/`
  (файлы `hr-ГГГГ-ММ-ДД_ЧЧММСС.sql.gz`). Хранятся **14 дней**, старые удаляются.
- Журнал копирования: `/var/log/hr-messenger-backup.log`.
- Сделать копию вручную: `bash /opt/hr-messenger/scripts/backup.sh`
- Список копий: `ls -lh /opt/hr-messenger/backups/`

Копии лежат на том же сервере и не спасут, если пропадёт сам сервер. Раз в неделю скачивайте свежую копию
к себе (на своём компьютере):

```
scp root@IP:/opt/hr-messenger/backups/hr-*.sql.gz .
```

Храните такие копии так же бережно, как саму базу: в них персональные данные кандидатов.

**Восстановление** (текущие данные будут заменены; перед этим скрипт сам сохранит их копию):

```bash
bash /opt/hr-messenger/scripts/restore.sh /opt/hr-messenger/backups/hr-2026-01-31_033000.sql.gz
```

Восстановление на **новый** сервер:
1. Установите приложение по разделу 5 (администратора можно не создавать — он придёт из копии).
2. В новом `/opt/hr-messenger/.env` замените значения `PHONE_ENC_KEYS`, `PHONE_HASH_KEY` и все строки `WA_...`
   на значения из сохранённого файла (раздел 7). Строку **`POSTGRES_PASSWORD` не меняйте** — на новом сервере база
   создана со своим паролем.
3. Примените настройки: `cd /opt/hr-messenger && docker compose --profile prod up -d --force-recreate`
4. Загрузите файл копии на сервер (на своём компьютере): `scp hr-....sql.gz root@IP:/opt/hr-messenger/backups/`
5. Восстановите копию командой `restore.sh`, как показано выше.

## 11. Если что-то пошло не так

**Сайт не открывается по `https://`, а скрипт написал «HTTPS пока не открывается».**
Почти всегда причина — DNS ещё не обновился или A-запись указывает не на тот IP.
1. Проверьте на dnschecker.org, что домен показывает IP вашего сервера.
2. Подождите (до нескольких часов). Caddy сам повторяет попытки получить сертификат — ничего перезапускать не нужно.
3. Посмотреть, что происходит:
   ```bash
   cd /opt/hr-messenger && docker compose --profile prod logs --tail 50 caddy
   ```
   Сообщения со словами `certificate obtained successfully` — всё получилось.
   `NXDOMAIN`, `no valid A records`, `timeout` — DNS ещё не готов или указан неверно.
4. Если долго не получалось, Let's Encrypt может временно (до часа) ограничить попытки. После исправления DNS
   перезапустите прокси: `docker compose --profile prod restart caddy`.

Также проверьте в панели хостинга, нет ли там отдельного файрвола: порты **80** и **443** должны быть открыты.

**Проверить, что приложение живо:**
```bash
cd /opt/hr-messenger
docker compose --profile prod ps          # все сервисы должны быть Up
curl http://127.0.0.1:8080/api/health     # ответ {"status":"ok"}
docker compose logs --tail 100 api        # журнал приложения
```

**Перезапустить всё:** `cd /opt/hr-messenger && docker compose --profile prod restart`

**Сервер перезагрузили** — приложение запустится само.

**Сменить домен:** поменяйте A-запись, затем в `/opt/hr-messenger/.env` исправьте `DOMAIN` и `CORS_ORIGINS`,
выполните `docker compose --profile prod up -d` и обновите Callback URL в кабинете Meta.
