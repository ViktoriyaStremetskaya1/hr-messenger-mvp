# Архитектура HR Messenger MVP

## Компоненты

| Сервис | Что делает |
|---|---|
| `web` | React + TS (Vite, Mantine), раздаётся nginx, проксирует `/api` |
| `api` | FastAPI: REST, приём webhook WhatsApp, SSE для inbox |
| `worker` | arq: очередь отправки с rate limit, рассылки по расписанию, напоминания, таймауты сценариев |
| `db` | PostgreSQL 16 |
| `redis` | очередь задач, token bucket лимитов, pub/sub для inbox |
| `wa-mock` (профиль `sandbox`) | эмулятор WhatsApp Cloud API + «телефон кандидата» в браузере, шлёт подписанные webhooks |

## Ключевые решения

- **Канал — абстракция `ChannelAdapter`** (send_template / send_text / send_buttons / send_list / verify_webhook / parse_webhook).
  Реализации: WhatsApp Cloud API (мок использует тот же адаптер с другим base URL), позже Telegram.
- **Webhook**: проверка `X-Hub-Signature-256` → сохранение сырого события → задача в очередь → мгновенный 200. Идемпотентность по `wamid`.
- **24-часовое окно**: `conversations.last_inbound_at`; вне окна разрешены только шаблоны (проверяется в API и в UI).
- **Сценарии**: граф в JSON (узлы: сообщение, кнопки, свободный ответ, условие, запись на слот, передача рекрутеру, установка статуса).
  Пошаговый редактор в MVP; визуальный (React Flow) можно добавить без смены движка.
- **Политика касаний** перед каждой отправкой рассылки: отписка → частота (раз в N дней) → рабочие часы Asia/Almaty (UTC+5) → лимит.
- **Статус воронки живёт в `applications`** (кандидат × вакансия). У кандидата — флаги «резерв» и «отписался».
  Результат скрининга — отдельное поле (`fit / unfit / review`).

## Безопасность

- Телефон: AES-256-GCM (`phone_enc`, с id ключа для ротации) + HMAC-SHA256 (`phone_hash`) для дедупликации и поиска + `phone_last4` для показа.
- Полный номер — только через `GET /api/candidates/{id}/phone`, каждый просмотр пишется в журнал.
- Телефоны маскируются в логах (`PhoneMaskFilter`).
- Пароли — argon2; сессия — JWT в httpOnly cookie `SameSite=Strict`.
- Роли: `admin` (пользователи, всё), `lead` (настройки, журнал, удаление), `recruiter` (работа с кандидатами и вакансиями).
- Журнал действий `audit_log`: входы (в т.ч. неудачные), изменения, импорт, просмотр телефона, настройки.
- Секреты только в `.env` (генерируется `scripts/gen-env.sh`).
- Согласие на ПДн в MVP не собирается; поля `consent_*` в схеме заложены.
