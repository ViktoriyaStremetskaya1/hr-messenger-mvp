# HR Messenger MVP

Инструмент массового подбора: база кандидатов, вакансии, WhatsApp-рассылки (официальный Cloud API),
скрининг, запись на собеседование, единый чат и аналитика. Интерфейс на русском,
сообщения кандидатам на русском и казахском.

Архитектура, схема и план по этапам: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

**Готово сейчас:** этапы 0–5: каркас, роли, журнал действий, база кандидатов с импортом, вакансии, WhatsApp Cloud API с песочницей, сценарии и скрининг, рассылки, запись на собеседование с напоминаниями, а также подготовка к развёртыванию на сервере.

Подключение боевого WhatsApp: [docs/WHATSAPP_SETUP.md](docs/WHATSAPP_SETUP.md).

## Быстрый старт (Docker)

Нужны Docker и Docker Compose v2.

```bash
./scripts/gen-env.sh                            # создаст .env со случайными секретами
docker compose --profile sandbox up -d --build   # с песочницей WhatsApp
docker compose exec api python -m app.seed   # тестовые данные (по желанию)
```

Откройте http://localhost:8080 (приложение) и http://localhost:9000 («телефон кандидата» в песочнице).

Тестовые учётки (пароль `Passw0rd!`): `admin`, `lead` (руководитель), `aigerim` / `dana` / `marat` (рекрутеры).

> ⚠️ Сохраните `PHONE_ENC_KEYS` и `PHONE_HASH_KEY` из `.env` в надёжном месте. Без них телефоны в базе не расшифровать.

Остановить: `docker compose down`. Удалить вместе с данными: `docker compose down -v`.

## Развёртывание на сервере

Боевой запуск на VPS с Ubuntu 24.04 (сервер в Казахстане), своим доменом и HTTPS — одной командой.
Пошаговая инструкция для не-программиста, обновление и резервные копии: [docs/DEPLOY.md](docs/DEPLOY.md).

## Локальная разработка

Нужны Python 3.12+, Node 22, PostgreSQL 16, Redis.

```bash
# backend
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp ../.env.example .env   # пропишите DATABASE_URL=postgresql+asyncpg://hr:hr@localhost:5432/hr и ключи
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed
.venv/bin/uvicorn app.main:app --reload --port 8000
```

```bash
# frontend (в другом терминале)
cd frontend
npm install
npm run dev      # http://localhost:5173, /api проксируется на :8000
```

```bash
# воркер фоновых задач (отправка сообщений, обработка webhook) — в отдельном терминале
cd backend && .venv/bin/arq app.worker.WorkerSettings
```

```bash
# песочница WhatsApp — в отдельном терминале; секреты те же, что в backend/.env
cd backend
WA_APP_SECRET=dev-app-secret WA_ACCESS_TOKEN=dev-token \
MOCK_WEBHOOK_URL=http://localhost:8000/api/webhooks/whatsapp \
.venv/bin/uvicorn app.wamock.main:app --port 9000
```

В `backend/.env` для песочницы: `WA_API_BASE=http://localhost:9000`, `WA_APP_SECRET=dev-app-secret`, `WA_ACCESS_TOKEN=dev-token`,
`WA_PHONE_NUMBER_ID=100000000000001`, `WA_BUSINESS_ACCOUNT_ID=200000000000001`.

Swagger: http://localhost:8000/api/docs

## Этапы 0–1: что проверить руками

**Вход и роли**
- [ ] Войти как `aigerim`. В меню нет пунктов «Пользователи» и «Журнал действий». Настройки только для просмотра.
- [ ] Войти как `admin`, создать пользователя, отключить его и убедиться, что он больше не может войти.
- [ ] Неверный пароль → в «Журнале действий» есть запись «Неудачный вход».

**Кандидаты**
- [ ] Фильтры: город, вакансия, статус, скрининг, резерв, теги. Поиск по ФИО, по полному номеру в любом формате и по 4 последним цифрам.
- [ ] Открыть карточку и нажать «Показать номер». Номер виден, а в журнале появилась запись «Просмотр телефона».
- [ ] Поменять статус и результат скрининга по вакансии. Статус обновился в таблице.
- [ ] Выделить несколько кандидатов и через «Действия с выбранными» добавить тег, отправить в резерв, привязать к вакансии.
- [ ] Добавить кандидата с номером, который уже есть (например, в формате `8 7xx…`). Должно появиться сообщение о дубле и открыться существующая карточка.

**Импорт**
- [ ] Загрузить .xlsx или .csv (UTF-8 или Windows-1251, разделитель `;` или `,`). Колонки ФИО, Телефон, Город, Вакансия, Источник должны определиться автоматически.
- [ ] После импорта показываются: сколько добавлено и обновлено, дубли в файле, строки с ошибками и с номером строки, ненайденные вакансии.
- [ ] Повторный импорт того же файла не создаёт дублей.

**Вакансии и настройки**
- [ ] Создать вакансию с FAQ и перевести её в архив. Удалить вакансию, к которой привязаны кандидаты, нельзя.
- [ ] В настройках изменить рабочие часы, частоту касаний и лимиты (под `lead`). Изменение попало в журнал.

## Этап 2: что проверить руками

Запуск с песочницей: `docker compose --profile sandbox up -d`. В шапке приложения должен быть значок «Песочница».

- [ ] «Шаблоны WhatsApp» → «Синхронизировать с Meta». Появится 9 одобренных шаблонов на русском и казахском.
- [ ] Создать кандидата со своим тестовым номером, открыть «Переписка WhatsApp». Свободный текст недоступен: окно 24 ч закрыто.
- [ ] Отправить шаблон `vacancy_offer · ru` с параметрами. Он появится в «телефоне кандидата» на http://localhost:9000 с кнопками.
      Статус в приложении: ✓ (отправлено) → ✓✓ (доставлено) → «прочитано» после открытия чата в «телефоне».
- [ ] В «телефоне» нажать «Да, интересно». В приложении придёт ответ, окно откроется, статус кандидата станет «Ответил».
- [ ] Ответить свободным текстом из приложения, сообщение придёт в «телефон». Диалог перейдёт к рекрутеру.
- [ ] В «телефоне» нажать «Закрыть окно 24 ч» и отправить текст из приложения. Сообщение станет красным с ошибкой «Истекло 24-часовое окно — нужен шаблон». Так ведёт себя и настоящий WhatsApp (ошибка 131047).
- [ ] Написать из «телефона» «СТОП». Кандидат отписан, пришло подтверждение, отправка заблокирована, в журнале есть запись «candidate.unsubscribe». Потом написать «СТАРТ» — подписка восстановится.
- [ ] Написать с нового номера через форму «Написать от кандидата». В базе появится кандидат с источником «WhatsApp (написал сам)».
- [ ] Отправить webhook с неверной подписью — ответ 401:
      `curl -i -X POST localhost:8080/api/webhooks/whatsapp -H 'X-Hub-Signature-256: sha256=00' -d '{}'`

## Этап 3: что проверить руками

- [ ] «Сценарии» → «Из шаблона» → «Предложение вакансии». Откроется редактор: слева шаги, справа настройки выбранного шага.
      Поменяйте текст или кнопку и нажмите «Сохранить» — версия вырастет. Если сценарий собран с ошибкой (например, переход на несуществующий шаг), сверху появится предупреждение.
- [ ] Создать кандидата с городом и **без языка**, открыть «Переписка WhatsApp», в блоке «Запустить сценарий…» выбрать
      «Предложение вакансии» и вакансию, нажать «Запустить».
- [ ] В «телефоне» (http://localhost:9000) по очереди:
  - «Қазақша» — дальше всё идёт на казахском;
  - «Иә, қызық» — придут детали вакансии и 4 вопроса;
  - ответить «Иә», «Иә», «1 жылдан көп», «Бір апта ішінде».
  В конце придёт сообщение «сіз бізге сәйкессіз», диалог перейдёт рекрутеру, в профиле будут «Подходит» и язык kk, ответы видны в переписке.
- [ ] Повторить, но на первый вопрос ответить «Нет». Результат «Не подходит», придёт предложение резерва; после «Да, сообщайте» кандидат в резерве.
- [ ] Ответить на вопрос с кнопками текстом «да» — бот поймёт. Ответить «а сколько платят?» — бот попросит выбрать вариант. После третьего непонятного ответа диалог уйдёт рекрутеру.
- [ ] Во время сценария написать кандидату из приложения — бот встанет на паузу (значок «бот на паузе»). «Вернуть боту» — бот продолжит со следующего ответа.
- [ ] «Скрининг» для кандидата, у которого язык известен, а 24-часовое окно закрыто, не запускается: сценарий начинается не с шаблона.
- [ ] «Реанимация резерва»: после «Да» кандидат видит список вакансий своего города, выбирает одну, и запускается скрининг по ней.
- [ ] «СТОП» во время сценария — сценарий завершается, кандидат отписан.

Сценарии создают, правят и удаляют только админ и руководитель. Рекрутеры запускают их для кандидатов.

## Этап 4: что проверить руками

- [ ] «Рассылки» → «Новая рассылка». Выберите сценарий «Предложение вакансии» и вакансию, сегмент заполнится по вакансии.
      Внизу покажется, сколько кандидатов в сегменте и сколько из них получат сообщение, а также кто будет пропущен и почему: отписались, писали недавно, уже идёт диалог.
- [ ] Нажмите «Запустить». В «телефоне» (http://localhost:9000) у кандидатов появятся шаблоны, на странице рассылки растёт воронка «Отправлено → Доставлено → Прочитано → Ответили → Прошли скрининг → Записаны».
- [ ] Ответьте за одного кандидата в «телефоне» и пройдите скрининг — в воронке изменятся «Ответили», «Прошли скрининг» и «Записаны».
- [ ] Запустите ту же рассылку ещё раз. Все будут пропущены по «частоте касаний» (по умолчанию не чаще одного раза в 3 дня, меняется в «Настройках»).
- [ ] «Настройки» → «Отправок в минуту: 2», запустите рассылку на 5+ человек. Сообщения уходят по 2 в минуту. Проверьте «Пауза», «Продолжить» и «Отменить».
- [ ] Поставьте в «Настройках» рабочие часы, в которые сейчас не попадает текущее время, и запустите рассылку — она будет ждать до начала рабочего окна.
- [ ] «Запланировать» на время через несколько минут — рассылка стартует сама.
- [ ] В «Кандидатах» отметьте несколько человек → «Действия с выбранными» → «Создать рассылку по выбранным».

## Этап 5: что проверить руками

- [ ] «Собеседования» → «Добавить слоты»: завтра, 10:00–13:00 по 30 минут, вакансия «Операционист». Получится 6 слотов.
- [ ] Запустите для кандидата «Предложение вакансии» и пройдите скрининг в «телефоне». Вместо «рекрутер свяжется» придёт список свободного времени
      («28 ноября, сб · 10:30», адрес) и пункт «Нет удобного времени». Выберите время — придёт подтверждение с датой и адресом.
- [ ] В «Собеседованиях» у слота будет кандидат и отметка «1/1», этот слот больше никому не предлагается. В карточке кандидата блок «Собеседования».
- [ ] Слот на 2 места (групповое): записать троих нельзя, третьему придёт «Это время только что заняли» и обновлённый список.
- [ ] «Нет удобного времени» — диалог уходит рекрутеру.
- [ ] Напоминания: воркер раз в 5 минут ищет записи, до которых осталось меньше 24 часов или меньше 2 часов, и шлёт шаблон с кнопками
      «Приду / Перенести / Отменить».
  - «Приду» отмечает подтверждение (✓ у записи).
  - «Перенести» предлагает новое время, старая запись станет «перенесено».
  - «Отменить» освобождает место.
  Если записались меньше чем за сутки, напоминание «за сутки» не придёт.
- [ ] После начала собеседования отметьте в «Собеседованиях» (меню «…») или в карточке «Пришёл» или «Не пришёл» — статус кандидата и воронка рассылки («Пришли») обновятся.
- [ ] Ручная запись: в карточке кандидата выберите свободное время → «Записать». С галочкой «Сообщить в WhatsApp» подтверждение уйдёт, если кандидат писал в последние 24 часа.

> Сценарии, созданные до этапа 5, сохранили старый текст шага записи («Рекрутер свяжется…»). Поправьте текст в конструкторе или создайте сценарий из шаблона заново.

## Принятые правила

- **Телефоны** приводятся к формату `+77XXXXXXXXX`. Принимаются только мобильные коды Казахстана (70x, 747, 750–751, 760–764, 771, 775–778): WhatsApp работает только на мобильных номерах. Список кодов задан в `backend/app/services/phone.py`.
- **Статусы:** новый → в рассылке → ответил → записан на интервью → пришёл / не пришёл → оффер → вышел. Отдельно флаги «резерв» и «отписался».
- **WhatsApp:** первое сообщение и любое сообщение вне 24-часового окна — только одобренным шаблоном. Стоп-слова: «стоп», «stop», «тоқта», «токта» (меняются в настройках). Слово «СТАРТ» возвращает подписку.
- **Сценарии:** если 24-часовое окно закрыто, сценарий должен начинаться с шаблона (или с выбора языка, когда язык неизвестен). Шаг «Запись на собеседование» до этапа 5 передаёт диалог рекрутеру. Без ответа сценарий ждёт столько часов, сколько указано у шага; ночью догоняющее сообщение не отправляется, оно уходит утром в рабочее время.
- **Рассылки:** первое сообщение — всегда одобренный шаблон (скрининг без шаблона в рассылку не поставить). Получателей проверяем в момент отправки, а не при запуске, поэтому «СТОП» сработает и для уже стоящих в очереди. Порция в минуту = «Отправок в минуту», в сутки — не больше «Отправок в сутки» по всем рассылкам. Воронка считает только результаты этой рассылки.
- **Собеседования:** бот предлагает до 9 ближайших слотов не раньше чем через 2 часа и не дальше 14 дней, подходящих вакансии кандидата (или «любая вакансия»). Последнее место в слоте защищено от двойной записи. Напоминания отправляются и вне рабочих часов: кандидат их ждёт (за 2 часа до собеседования в 9:00 — в 7:00).
- **Время:** Asia/Almaty (UTC+5). Часовой пояс берётся из пакета `tzdata`, а не из системы контейнера.
